# Требования к продукту

Документ фиксирует возможности учебной платформы собеседований.

## Функциональные требования

| ID | Требование |
|---|---|
| FR-001 | Пользователь входит локальной учётной записью. Роль берётся из демо-групп. |
| FR-002 | Пользователь управляет данными стажёров и их статусами. |
| FR-003 | Пользователь планирует и отслеживает собеседования. |
| FR-004 | Пользователь управляет офферами, долгами и связанными сущностями. |
| FR-005 | Менеджер просматривает аналитику по собеседованиям и офферам. |
| FR-006 | Система предоставляет REST API для UI и разрешённых интеграций. |
| FR-007 | Длительные операции выполняются асинхронно через Celery. |
| FR-008 | Пользователь выполняет семантический поиск по доступным данным. |
| FR-009 | Клиент MCP вызывает операции через `POST /mcp`. Набор тулов зависит от демо-роли. |
| FR-010 | Сотрудник открывает «Что нового» из оболочки. Студент портала кнопку не видит. |
| FR-011 | Карточка стажёра доступна администратору, своему менеджеру и ролям просмотра. Пароли и внешние сессии в карточке не хранятся. |

## Нефункциональные требования

- Локальный адрес: `http://localhost:8000`.
- Доступ определяется ролью демо-учётки.
- Секреты и пользовательские файлы не хранятся в Git.
- Изменение API сопровождается обновлением `docs/api/openapi.yaml`.
- Backend покрывается pytest; frontend — Vitest.
